HEADLINE — RECOMMENDATION + BASE-CASE RETURN LEADS:
  investment_thesis MUST open with a paragraph that leads with the recommendation
  (BUY / WATCH / PASS from math_json.recommendation) and the base-case return
  (math_json.base_case_return) versus the current price — i.e. what a buyer earns if
  the base case plays out. Then frame the scenario spread (bull vs bear price and EPS)
  and the expected value. This is the single most important paragraph.

  The reverse-DCF (implied_fcf_cagr) is a supporting REALITY CHECK, not the headline:
  cover it in reverse_dcf_commentary, not the opening line. When
  math_json.reverse_dcf_unstable is true, explicitly caveat that the implied growth
  figure is unreliable because the current free-cash-flow base is very small, and lean
  on the scenario EPS/price framework instead.

B5 — FY+2 FRAMING:
  All forward references use relative framing: "FY+2" for two fiscal years out,
  "FY+1" for next fiscal year, "TTM" for trailing twelve months.
  Never write calendar year labels ("2026", "2027") — the report date is {today_date}
  and the rendering layer converts FY+N to calendar years.
  When citing the forward EPS used in math_json.scenario_eps, call it "FY+2 EPS".

B6 — FORBIDDEN VOCABULARY — NEVER WRITE THESE:
  × "Sharpe"  — use "prob_loss" or "expected_return_pct" to express risk/reward
  × "capture" — use "benefit from", "benefit of", "upside from", "downside protection"
  × "DEGRADED" — never write this word in any section
  Violations will fail automated audit. No exceptions.

CITATION DISCIPLINE:
  Every number in your narrative MUST be verbatim from math_json, pass1_json, or baseline_json
  UNLESS the section is explicitly marked QUALITATIVE below.
  DO NOT compute, derive, round differently, or recall from training data.
  NEVER write raw field paths in prose. Write the NUMBER in plain English, not the JSON
  path that produced it. WRONG: "a base target of 338.90 per math_json.price_target.base_mid".
  RIGHT: "a base-case target of 338.90". The reader must never see "math_json", "pass1_json",
  "baseline_json", or a dotted field path anywhere in the narrative.
  NO dollar signs ($) — write "41.22" not "$41.22". Write "14.5 billion" not "$14.5B".
  NO open-ended ranges ("12%+") unless that exact bound appears in source.
  If a number is not in source, use qualitative direction (growing, expanding, contracting).

QUALITATIVE SECTIONS:
  The following sections draw on training knowledge about the company. You do NOT need to cite
  every number from math_json/baseline_json. Label approximate percentages as "(estimate)".
  Do not fabricate specific dollar figures — use directional language instead.
  Qualitative sections: business_overview, concentration_and_dependencies, competitive_position,
  growth_drivers_and_moats (qualitative portions only).

STYLE:
  Declarative and specific. Numbers carry the argument; prose provides context.
  Write for a portfolio manager who has 60 seconds per paragraph.
  No marketing language ("world-class", "dominant", "exceptional").
  No hedging boilerplate ("it is worth noting", "it should be mentioned").

WORD COUNT:
  Total words across ALL sections MUST NOT exceed 7000.
  Target 5000-6500. One tight paragraph beats two loose ones.

conclusion (REQUIRED — ≥2 paragraphs, \\n\\n separated):
